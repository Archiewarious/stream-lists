# Stream Lists: Games & Movies, архитектура

Twitch-расширение (Panel). Главный сценарий: **список фильмов на 50+ позиций**, что в очереди и что уже
посмотрели. Списки игр и «своё» работают так же. Фильмы можно импортировать из рулетки Pointauc.
Дизайн утверждён: [`docs/design/mockup-v5.html`](design/mockup-v5.html) (скриншоты: `mockup-v5*.png`).
Материалы для ревью Twitch: [`docs/review/`](review/README.md). Юридические страницы: [`docs/legal/`](legal/).

## Решения пользователя (не менять без него)

- Статусы только **Очередь → Просмотрено**. «Смотрим сейчас» убран (фильм короткий, переключать неудобно).
- Дата просмотра ставится автоматически при «Просмотрено».
- Постеры и год — из TMDB, подбираются при добавлении; стримеру ничего не загружать.
- Тема по умолчанию «Лиловая лисичка» + выбор тем и своих цветов. Зрители видят тему стримера.
- Зрителю главное — прочитать длинный список и найти фильм («а это уже смотрели?»).

Решения после аудита (2026-10-11…12), на которых держится код:

- Очередь упорядочена по баллам Pointauc (больше баллов выше), записи без баллов идут следом в порядке стримера.
- В панели нет кнопки «Списком» и «Сразу в просмотренные» в импорте Pointauc: обе остались в окне настроек.
- В карточке фильма нет внешней ссылки на TMDB; логотип и уведомление TMDB есть там и в окне настроек.
- Два лота с одним названием: порядок задаёт лот с большей ставкой.
- Лот, который стример удалил из списка или скрыл из «На проверке», в импорте больше не появляется.
- Тариф Cloudflare Free: лимиты ниже подобраны под него. Лимитов частоты запросов зрителей нет.

## Поток данных

```
panel.html / config.html ──JWT──► Worker ──► D1 (все данные)
  (стример: правка)                 ├──► TMDB (поиск и карточка, ключ только в Worker)
                                    ├──► Pointauc API (лоты; токен стримера зашифрован в D1)
                                    └──► Twitch Helix: снимок → config segment + PubSub broadcast

panel.html у зрителя:
  1. снимок из Twitch config: первый экран без запросов к Worker, дальше PubSub
  2. GET /api/viewer/items: следующая страница очереди или истории (по 30) при прокрутке
  3. GET /api/viewer/search: поиск на сервере (до 30 результатов и общее число)
  4. GET /api/movie/:id: карточка фильма по клику
  5. GET /api/viewer/snapshot: снимок, если Twitch отдал нечитаемый
  Постеры: image.tmdb.org напрямую, только для видимых строк (w92).
```

- **Снимок** (`worker/src/snapshot.ts`): JSON `v: 2` с короткими ключами, не больше 5000 байт. Для каждого списка
  кладутся первые элементы очереди и истории; число элементов подбирается ступенями `[очередь, история]`:
  `[25,15] [20,12] [15,8] [10,5] [5,3] [2,1] [1,1] [1,0] [0,0]`, берётся первая, что влезает. Полные счётчики
  (`qn`, `wn`) идут всегда. Клиент принимает `v ≥ 2`.
- **Публикация** (`publish.ts`): снимок уходит в config segment и PubSub одним проходом. Публикации канала идут не
  чаще раза в 3,1 с (Twitch принимает около 20 записей конфигурации в минуту): пачка быстрых правок уходит
  последним состоянием. Если Twitch не принял снимок, канал помечается `snapshot_stale`, и cron отправляет его
  ещё раз.
- **Какие запросы публикуют.** У каждого маршрута в таблице `routes.ts` есть признак `publishes`: он меняет то, что
  видит зритель (список, элемент, порядок, тема). Токен Pointauc, скрытие лота и чтения снимок не меняют.
- **Авторизация**: Twitch JWT в `Authorization: Bearer`. Worker проверяет HS256 секретом расширения (base64).
  Канал берётся из JWT, не из запроса. Писать может только `role = broadcaster`, остальным маршрутам нужен любой
  валидный JWT. Ответы: 401 без токена, с просроченным или чужим, 403 зрителю на маршрут стримера, 404 на чужой
  список или элемент (изоляция каналов).
- **CORS** `*`: токен идёт в заголовке, не в cookie.

## Данные (D1)

```
lists:        id, channel_id, title, kind (movies | games | custom), created_at
items:        id, list_id, title, year, poster_path, tmdb_id, tmdb_type (movie | tv),
              status (queue | watched), position, added_at, watched_at, source (manual | pointauc),
              points (баллы Pointauc), lot_id, rating (1–10, только у просмотренного), match_tried_at
channels:     channel_id, theme (JSON: { preset } | { primary, accent }),
              pointauc_token (AES-GCM), pointauc_list_id (список, который ведёт автосинк),
              pointauc_synced_at, pointauc_lots_hash, pointauc_due_at, pointauc_failing_since,
              snapshot_at, snapshot_stale
pending_lots: id, list_id, lot_id, name, points, status (pending | dismissed), created_at, seen_at,
              UNIQUE (list_id, lot_id)
```

Элементы удаляются каскадом вместе со списком. Повтор названия определяется по нормализованному названию
(`normalizeTitle`: NFC, нижний регистр, ё как е, лишние пробелы). Отдельного UNIQUE-индекса по `(list_id, lot_id)`
нет: повторы отсекает условная вставка `INSERT … SELECT … WHERE NOT EXISTS` в `insertItem`.

Порядок (`ITEM_ORDER` в `store.ts`, один на все запросы): очередь по баллам по убыванию, затем по `position`;
просмотренное по дате просмотра, новое сверху.

## Worker API

Колонка «Кто»: **стример** (`role = broadcaster`) или **любой** (любой валидный JWT канала). Столбец «Публикует»
показывает признак `publishes` из `worker/src/routes.ts`.

| Метод и путь | Кто | Публикует | Что |
|---|---|---|---|
| `GET /api/channel` | стример | | все списки и элементы, тема, `pointauc` (токен есть и читается), `pointauc_list_id`, `pending` |
| `POST /api/lists` | стример | да | список (до 20) |
| `PATCH /api/lists/:id` | стример | да | название, вид |
| `DELETE /api/lists/:id` | стример | да | список с элементами; автосинк этого списка останавливается |
| `PUT /api/lists/:id/order` | стример | да | порядок очереди (`ids`, различные); часть очереди делит между собой свои места |
| `POST /api/lists/:id/match-missing` | стример | если `updated > 0` | постеры для названий без постера (до 20 за вызов, давно не пробованные первыми) |
| `POST /api/items` | стример | да | элемент; повтор названия → 409 `Already in the list` |
| `POST /api/items/bulk` | стример | да | «Списком» (до 200); ответ: `added`, `skipped`, `unchecked` (сколько названий без проверки TMDB) |
| `PATCH /api/items/:id` | стример | да | пишутся только присланные поля; статус, дата и место считаются в SQL |
| `DELETE /api/items/:id` | стример | да | удаление; лот Pointauc записывается скрытым и не возвращается |
| `GET /api/tmdb/search?q=&lang=` | стример | | подсказки: название, год, постер (без ключа 503) |
| `PUT /api/theme` | стример | да | тема и цвета |
| `PUT /api/pointauc/token` | стример | | подключить (токен проверяется запросом к Pointauc, хранится AES-GCM) |
| `DELETE /api/pointauc/token` | стример | | отключить: токен и автосинк |
| `GET /api/pointauc/lots?list_id=` | стример | | лоты и статус: новый / в очереди · N / смотрели <дата>; скрытые не показываются |
| `POST /api/pointauc/import` | стример | да | импорт выбранных `lot_ids` (до 200); лоты читаются из Pointauc на сервере |
| `PUT /api/pointauc/sync` | стример | сам проход | включить автосинк для списка (`list_id`) или выключить (`null`) |
| `POST /api/pointauc/refresh` | стример | сам проход | проход синка по требованию (панель стримера зовёт каждые 12 с) |
| `POST /api/pending/:id/accept` | стример | если `added` | лот из «На проверке» в очередь (название можно поправить) |
| `DELETE /api/pending/:id` | стример | | скрыть лот |
| `GET /api/viewer/items?list_id=&status=&offset=` | любой | | страница очереди или истории, 30 штук |
| `GET /api/viewer/search?list_id=&q=` | любой | | поиск в списке: ≤ 30 результатов и `total`; сначала просмотренные, у очереди место |
| `GET /api/viewer/snapshot` | любой | | тот же снимок, что в Twitch |
| `GET /api/movie/:id?type=&lang=` | любой | | карточка: описание, жанры, длительность, оценка; только для `tmdb_id` из списков канала |
| `GET /api/viewer/channel` | любой | | весь канал; оставлен для zip 0.0.1, убрать после выпуска новой версии |

Зрителю не отдаются `lot_id`, `added_at`, `match_tried_at` и ссылки TMDB. Коды ошибок: 400 валидация,
409 повтор или лимит или токен Pointauc, который надо ввести заново, 502 Pointauc или TMDB не ответили,
503 не настроен ключ TMDB или шифрования.

Секреты Worker: `EXTENSION_SECRET`, `TMDB_API_KEY`, `TOKEN_ENCRYPTION_KEY`; на время ротации ещё
`EXTENSION_SECRET_PREVIOUS`. Адрес: `https://stream-lists.begidan32.workers.dev`
(Cloudflare-аккаунт begidan32, D1 `stream-lists`, cron `* * * * *`).

### Ротация `EXTENSION_SECRET`

Worker принимает JWT, подписанные текущим или предыдущим секретом, а Helix-запросы подписывает текущим.

1. В консоли Twitch создайте новый секрет расширения.
2. Сразу запишите старое значение: `wrangler secret put EXTENSION_SECRET_PREVIOUS`.
3. Запишите новое: `wrangler secret put EXTENSION_SECRET`. Токены зрителей, выданные до смены, продолжают работать.
4. Когда старые токены истекли и старый секрет отозван в консоли: `wrangler secret delete EXTENSION_SECRET_PREVIOUS`.

Если старый секрет утёк, `EXTENSION_SECRET_PREVIOUS` не задавайте: отзовите старый в консоли и запишите новый.
`TOKEN_ENCRYPTION_KEY` менять нельзя без повторного ввода токена Pointauc: старые шифротексты не расшифруются
(окно настроек покажет «Pointauc не подключён»).

## Синхронизация с Pointauc

Данные лотов Worker берёт у Pointauc сам (`GET https://pointauc.com/api/oshino/lots` с токеном стримера): Pointauc
передаёт запрос в открытую вкладку pointauc.com, поэтому при закрытой вкладке или неверном токене ответ не приходит.

- **Импорт вручную** (окно настроек, «Из Pointauc»): стример выбирает лоты, Worker добавляет их в очередь или
  в просмотренное. Лот, который уже есть в списке, получает свежие баллы. Лот, удалённый или скрытый стримером,
  в диалоге не показывается и не импортируется.
- **Автосинхронизация** (включается для одного списка): новый лот сразу идёт в очередь, если TMDB знает название
  и у записи не меньше 20 голосов. Иначе лот попадает в «На проверку» (`pending_lots`), где стример принимает его,
  поправив название, или скрывает. Игры и «Своё» без TMDB: все новые лоты на проверку. Лот, который уже побывал
  в «На проверке» или был удалён из списка, второй раз не появляется.
- **Сопоставление**: по нормализованному названию, `lot_id` лишь дополняет его. Id лота Pointauc после перезагрузки
  вкладки может измениться, поэтому один `lot_id` не считается надёжным (`fastId` не используется).
- **Опрос из панели**: пока панель стримера открыта и вкладка видна, она зовёт `POST /api/pointauc/refresh`
  каждые 12 с; при сбое пауза растёт вдвое до 2 минут. Сервер не делает больше одного прохода в 10 с на канал.
- **Cron** (раз в минуту, 4 канала за запуск): сначала повторяются публикации, которые Twitch не принял, потом
  синхронизируются каналы, чья очередь пришла (`ORDER BY pointauc_due_at`).
- **Если Pointauc не отвечает**: cron спрашивает канал реже, через 1, 2, 4 … минуты, не реже раза в час. Через 30
  дней без ответа автосинк останавливается. Он возобновляется сам, когда стример открывает панель или окно
  настроек (`GET /api/channel`). Токен, который не расшифровывается (сменился ключ), даёт 409, и панель
  показывает «Pointauc не подключён».
- **Отпечаток лотов** (`pointauc_lots_hash`): если Pointauc ответил теми же лотами, что в последнем полном
  проходе, список не читается и ничего не пишется. День входит в отпечаток, чтобы раз в сутки скрытые лоты,
  которые ещё в аукционе, получили отметку `seen_at`.
- **Скрытые лоты** забываются через 90 дней после последнего появления в аукционе: cron удаляет по 50 за запуск
  (индекс `pending_lots_gone`).
- **Без Pointauc** всё работает: названия добавляются по одному, «Списком» или с подсказками TMDB, очередь идёт
  в порядке стримера, зрители видят то же самое.

## Фронтенд

React 19 + Vite + TypeScript, Mantine (поведение: Combobox, Modal, Popover, ScrollArea) + Tailwind
(внешний вид), dnd-kit (порядок очереди), i18next ru/en (язык из `?language=` Twitch, вне Twitch из браузера).
Шрифты в сборке: Great Vibes (заголовки, кириллица в нём есть), Nunito 600–800 (текст), только woff2,
`@font-face` лежат в `src/app/styles.css`.
Тема: CSS-переменные. У пресета 4 цвета (`--bg`, `--primary-hi`, `--primary-lo`, `--accent`, см. `app/presets.ts`),
стекло, чипы и сияние выводятся из них через `color-mix()`; Mantine перекрашивается через `cssVariablesResolver`.
Для своих цветов текст на кнопках выбирается по контрасту (`pickOnColor`). Пресеты: Лиловая лисичка, Фиалка
(id `twitch` в данных и снимке не менялся), Закат, Мята, Лёд, Вишня + свои цвета. Всегда тёмная.
Витрина компонентов: `npm run dev` → `/ui.html` (в сборку не входит).

Структура по соглашениям Pointauc (`AGENTS.md`):

```
extension/src/
  app/                       провайдеры, тема (пресеты → CSS-переменные)
  pages/{panel,config}/      композиция экранов; panel: ViewerPanel (данные зрителя) + ViewerPanelView,
                             AuthorSide (редактор стримера, грузится lazy), AuthorPanel
  domains/lists/             списки, элементы, очередь/просмотрено, группировка по месяцам, lib/ (чистая логика)
  domains/movies/            поиск TMDB, постеры, карточка фильма
  domains/integrations/pointauc/  импорт лотов, «На проверку»
  domains/appearance/        экран «Оформление»
  shared/{twitch,api,ui}/    Twitch.ext + имитация (fanOut: один подписчик onAuthorized), клиент Worker,
                             общие компоненты (TmdbAttribution, AuthorCredit, ErrorBoundary)
```

### Сборка

`npm run build` (в `extension/`) делает `tsc --noEmit` и `vite build`.

- `build.minify: false`: Twitch просит читаемый JS (правила 2.5 и 2.6). Общий чанк библиотек называется
  `vendor-*.js`, стили `styles-*.css`.
- Зритель загружает `panel`, `vendor` и `styles`. Редактор стримера (`AuthorSide`, dnd-kit, модалки, формы) это
  отдельные чанки, которые грузятся только при роли `broadcaster`.
- CSS Mantine подключается по компонентам списком `@import '@mantine/core/styles/<Имя>.layer.css'` в
  `src/app/styles.css`, в порядке из `@mantine/core/styles.layer.css`. Новый компонент Mantine нужно добавить в
  этот список, иначе он будет без стилей.
- Twitch helper стоит первым скриптом в `<head>` обоих HTML. Иконки Tabler импортируются поимённо и попадают в
  бандл только используемые.
- Размеры (gzip) и сравнение до/после: `docs/audit/REPORT.md`, раздел «Размеры».

Модули `worker/src/{snapshot,pointauc,tmdb,theme,jwt,crypto,base64}.ts` общие с расширением (алиас `@worker`),
в них нет API, которые есть только в Workers.

## Этапы и ревью

Расширение 0.0.1 на ревью не отправлялось. Любая правка файлов расширения после выпуска это новая версия и новое
ревью, поэтому логика держится в Worker. Worker и данные меняются без ревью.

В консоли Twitch перед ревью: адрес Worker в список запросов (URL fetching), `image.tmdb.org` в список
изображений (оба замораживаются после отправки), поля версии: см. [`docs/review/README.md`](review/README.md).

## Ограничения Twitch

- Сегмент конфигурации 5 КБ; панель 318 px в ширину, высота по консоли (до 500 px); окно настроек 700 px высотой.
- Helper Twitch грузится только с их CDN, без SRI (файл обновляется на месте).
- Chrome 142+ (Local Network Access) не пускает `localhost` внутрь twitch.tv: проверка на Twitch идёт через
  «Тест на сервере» (zip в консоль), разработка в браузере с имитацией Twitch.
- В HTML стоит `<meta name="darkreader-lock">`: Dark Reader иначе перекрашивает iframe.
- `Twitch.ext.onAuthorized` хранит только последний обработчик: подписываться через `twitchApi.onAuthorized`.

## Разработка

```
# extension/
npm run dev          # http://[::1]:5173/config.html, /panel.html, /panel.html?role=viewer, /ui.html
                     # Twitch имитируется, запросы идут в локальный Worker с JWT на тестовом секрете
npm test             # чистая логика (node, без jsdom)
npm run build        # dist; zip: cd dist && /c/Windows/System32/tar.exe -a -cf stream-lists.zip panel.html config.html assets

# worker/
npm test             # HTTP-слой на node:sqlite (TEST_D1=workerd: на настоящей локальной D1)
npm run typecheck    # wrangler types + tsc
npm run dev:ext      # применяет миграции к локальной D1 и поднимает wrangler dev на 127.0.0.1:8787
                     # с тестовым секретом; ключ TMDB для подсказок в .dev.vars (без него подсказки отвечают 503)
npm run deploy       # predeploy (typecheck + тесты), миграции на удалённую D1, выкладка
```

Локальная D1 в `worker/.wrangler/state` засеяна тестовыми фильмами. Токен Pointauc в локальной базе настоящий,
и опрос из локальной панели ходит в pointauc.com.
